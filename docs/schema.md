# Database and contracts

`contracts/v2/` and `Challenger.Siem.Contracts.V2` define the Linux-only public boundary. Event sources are `linux_journal`, `linux_audit`, `inventory_diff`, and `agent_health`; every event declares `platform=linux`, a stable `source_id`, a checkpoint, deterministic deduplication metadata, and data-handling metadata. The additive schema examples identify `linux-package-inventory-diff` as the current mandatory package observation source and `linux-package-management` as supplemental direct journal evidence without narrowing the open stable-ID contract. `asset-inventory.schema.json` defines both legacy unpaged snapshots and the additive bounded generation/page summary contract. `telemetry-coverage.schema.json` includes additive liveness-monitor, retention-scheduler, and per-agent history-readiness fields. `process-activity-investigation.schema.json` defines the cited, independently capped process/lineage/network/privilege/change/source-qualification response used by the read-only MCP workflow.

The PostgreSQL schema is [001_linux_v2.sql](../server/Siem.Api/Database/001_linux_v2.sql). It includes agents, events, heartbeats, source health, inventory, detections, alerts, cases, graphs, saved searches, audit, and retention metadata. Inventory paging metadata and the additive nullable process-instance/provenance fields stay in existing bounded JSON projections; exact process queries remain constrained by agent, source, and event-time indexes before inspecting those projections. Release 2.12.0 adds no columns, migration, or telemetry backfill. The schema deliberately contains no endpoint fields or tables for other operating systems, browser UI state, embedded chat sessions, OAuth, user accounts, or login sessions.

The optional traffic map reads existing event/source-health rows and does not add PostgreSQL state. Its separate private SQLite cache is an implementation detail, not a public schema: it stores only normalized IP location/ASN/status/provider/timestamp fields and UTC-day quota counts. It contains no raw provider response, event payload, browser credential, or UI session state.

Apply it only to an empty database with `./scripts/apply-schema.sh`; verify with `./scripts/validate-schema.sh`. Back up 1.x data separately if it must be retained. Version 2 does not transform an existing schema.
