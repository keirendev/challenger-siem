# Linux coverage matrix

This matrix is the concise operator view. Exact parser, applicability, checkpoint, and validation semantics are defined by `LinuxTelemetrySourceCatalog` and [Linux host coverage](linux-host-coverage-spec.md).

| Level/source | Security awareness | Default and privilege boundary | Important limitations | Source-health behavior |
| --- | --- | --- | --- | --- |
| L0 heartbeat/inventory | Agent availability, version, resource/queue pressure, host/kernel/boot posture, packages, services/timers, listeners, mounts, firewall/SSH/MAC/Secure Boot summaries | Enabled; fixed read-only commands/files under the existing non-root service identity; no package refresh or policy change. CachyOS/Arch-family fallbacks use only fixed UFW, AppArmor-kernel, EFI Secure Boot, and OpenSSH paths | Inventory is periodic, bounded, and excludes raw command output, rules, addresses, file contents, account details, and credential config content | Per-snapshot success, unavailable, not-applicable, denied, timeout, malformed, and truncation states; heartbeat gaps remain explicit |
| `linux-journal-l1` | Boot, kernel, core system and service records | Enabled; system journal only by default through fixed `journalctl` invocation; no new group/capability | Sees only records already readable and retained; not every security family is structured at L1 | Durable cursor/checkpoints; permission, invalid cursor, rotation, malformed/binary, pressure, lag, gap, and acknowledgement state |
| `linux-login-session`, `linux-ssh` | PAM/logind login/session and role-specific SSH authentication/session activity | L2 opt-in; reuses the L1 cursor and permissions; SSH applicability follows role/producer evidence | Quiet health does not prove activity; structured producer fields take precedence; broader journals require separate privacy review | Current journal observation can keep a proven quiet source fresh; denied/missing producer visibility remains degraded |
| `linux-sudo-su` | Privilege use and structured command context | L2 opt-in; no sudo/PAM configuration change | Only journal-visible sudo/su activity; command text is bounded/high-sensitivity and secret-pattern sanitized | Missing producer visibility or journal gaps lower detection confidence |
| `linux-cron-timers` | Cron/systemd timer execution and scheduled persistence context | L2 opt-in; no task or timer mutation | Requires prior cron or timer producer evidence; does not read crontabs/unit files | Quiet periods remain healthy only after bounded producer evidence; families stay independently observed/not-observed |
| `linux-package-management` | Install/update/remove activity plus bounded package posture | L2 opt-in; fixed read-only inventory/journal; no refresh/install/remove | Journal coverage can remain degraded on distributions/producers that do not journal changes | Inventory determines applicability; real matching records establish event visibility |
| `linux-firewall` | Existing allow/deny/policy-change journal evidence and bounded posture | Optional L2; no logging/rule/service change | Useful only when logging is already enabled and readable; no packet/payload capture | Unsupported/not-applicable/quiet/degraded are distinct; optional absence does not masquerade as collected evidence |
| `linux-kernel-security`, `linux-service-change`, `linux-agent-log-tamper` | Kernel/LSM/module, systemd lifecycle, agent/log visibility changes | L2 opt-in; shared journal only | Rare events and quiet periods do not prove absence; no kernel/service mutation | Fresh shared-journal observations keep quiet visibility current; active gaps remain fail-closed |
| `linux-agent-self-integrity-snapshot` | Added/changed/deleted/unreadable metadata and hashes for the fixed agent allowlist | Optional L3, disabled; exact plan hash; no arbitrary path/recursion/capability | Configuration content is never read/hashed; cannot attest against root/kernel compromise | Durable sequences, pressure pause, bounded gaps/drop/recovery; disable cleanup is state-file only |
| `linux-process-snapshot-diff` | Bounded observed/changed/disappeared process metadata | Mandatory for an L3 target, disabled by default; exact plan hash; fixed procfs reads | Polling can miss short-lived processes and cannot prove exec/exit time; excludes environment, memory, maps, stacks, FDs, cwd/root | Partial/race/denied/timeout/cap/pressure and restart-baseline states are explicit |
| `linux-network-socket-snapshot-diff` | Bounded TCP/UDP listener/connection tuple differences | Mandatory for an L3 target, disabled by default; exact plan hash; fixed procfs reads | No payload, DNS, Unix path, packet timing, or process attribution | Partial/truncated/gap/pressure/restart-baseline states are explicit |
| `linux-host-behaviour-metrics` | Coalesced CPU, memory, load, disk/network counter and PSI pressure context | Mandatory for an L3 target, disabled by default; exact plan hash | Aggregate samples only; missed intervals are not backfilled; one sample is not sustained impact | Counter reset, unavailable values, discontinuity, pressure, and freshness remain explicit |
| `linux-policy-posture-drift`, `linux-agent-performance-slo` | Approved posture fingerprint drift and rolling agent CPU/RSS/write/queue guardrails | Mandatory L4, disabled; exact plan and baseline hashes; all lower mandatory sources healthy | Fingerprints do not reveal exact changed values; rolling SLO does not replace private per-collector benchmarks | Warm-up, incomplete baseline, mismatch, drift, unavailable counter, breach, pressure, gap, stale/future evidence block strict L4 |
| `linux-role-*` journal packs | Structured service/security context for declared web, database, DNS, file, container, and identity roles | Role-specific L4; shared journal; no application-file reader or logging change | Fixed unit/identifier matches only; excludes DB/file/DNS/container payloads and secrets | Every declared applicable role must be healthy; quiet health is not proof of a role event |
| `linux-audit-framework` | Potential existing audit record coverage | Unsupported and disabled | No collector, audit rule, daemon, backlog, permission, or package change is implemented | Always reported honestly as unsupported; optional unsupported capability is visible without pretending evidence exists |
| eBPF/broad FIM/packet or process-content collection | Deferred | Not present | No kernel program, broad file watch, packet payload, process memory/environment, keystroke, screenshot, browser, shell-history, or secret-store collection | Absence is an intentional product boundary, not a healthy source |

Built-in rules, evidence, suppression/grouping, confidence lowering, and false-positive guidance are listed in [Linux detections](linux-detections.md). Coverage must be read together with source health: no event can establish that an unavailable source was complete.
